scorr vs &scorr 质量鸿沟深度技术分析
一、算法架构代差：真正的根本原因
SSW (scorr) — k步归纳法（真正的归纳证明）
核心循环在 sswSweep.c:380-449，Ssw_ManSweep：


1. Ssw_FramesWithClasses(p)
   → 构造 k+1 帧展开 AIG (pFrames)
   → 前 k 帧：对每个候选等价对 (A,B)，向 SAT solver 添加硬约束子句 XOR(A,B)=0
     （Ssw_FramesConstrainNode → Ssw_NodesAreConstrained）
   → 第 k+1 帧：所有候选等价在此帧被查询

2. 对每个候选等价对 (repr, obj)，调用 Ssw_NodesAreEquiv()：
   → UNSAT: 立刻合并，在 pFrames 中替换节点引用
   → SAT:   立刻调用 Ssw_ManResimulateWord() 重模拟，分裂多个类
   → TIMEOUT: 从类中移除

3. 所有节点在同一个持久 SAT 实例中顺序处理
关键：同一个 SAT solver 实例处理该轮所有等价查询。每次 UNSAT 证明的学习子句保留在求解器中，帮助后续查询。

Cec (&scorr) — 推测化简 Miter（非归纳）
核心循环在 cecCorr.c:1006-1090，Cec_ManLSCorrespondenceClasses：


1. Gia_ManCorrSpecReduce(pAig, nFrames=1, fScorr=1, ...)
   → 构造组合 Miter：
     - 所有候选等价通过"结构替换"施加（等价节点的逻辑锥被直接合并）
     - 每对候选等价生成一个 XOR 输出
   → 输出：一个无寄存器的组合 AIG

2. Cbs_ManSolveMiterNc / Cec_ManSatSolveMiter 批量求解所有输出

3. 批量收集反例，然后调用 Cec_ManResimulateCounterExamples()

4. 丢弃整个 SAT 实例，下一轮重新构建
关键：每轮迭代都从零构建新的 SAT 问题。上一轮的所有学习子句全部丢弃。

二、五大质量差异的技术根因
差异 1：增量 SAT vs 批量 SAT（最关键）
维度	scorr (SSW)	&scorr (Cec)
SAT实例生命周期	跨越整个一轮 sweep 的所有节点查询	每次迭代重新构建，学习子句清空
传递性利用	证明 A≡B 的学习子句直接帮助证明 C≡D	无，靠结构替换隐式传递
节点间依赖	拓扑顺序处理，上游节点合并立即传播到下游	同一迭代内无传播，下一轮才生效
反例反馈	找到反例 → 立即重模拟 → 立即分裂类 → 下一个节点已受益	积攒所有反例 → 批量重模拟 → 下一轮才生效
代码证据 — SSW 中证明立即传播 (sswSweep.c:219-228):


if ( RetValue == 1 )  // proved equivalent
{
    pObjFraig2 = Aig_NotCond( pObjReprFraig, pObj->fPhase ^ pObjRepr->fPhase );
    Ssw_ObjSetFrame( p, pObj, f, pObjFraig2 );  // 立即在 frames AIG 中替换！
    return 0;
}
差异 2：k步假设子句 vs 结构推测化简
SSW 在 Ssw_FramesWithClasses 中对每个候选等价 (A,B) 添加硬子句 XOR(A,B) = 0 到 SAT 数据库。这意味着 SAT solver 知道："如果 A 不等于 B，则已有子句冲突"。这使得后续查询可以直接利用 CDCL 学习到的蕴含关系。

&scorr 的 Gia_ManCorrSpecReduce 用结构替换而非子句：当 B 有代表元 A 时，B 的扇入锥被 A 的锥替代。这在逻辑上等价，但 SAT solver 看到的是更小的电路，丢失了一些"哪些节点等价"的语义信息，无法做跨等价对的学习。

差异 3：初始模拟质量
SSW 默认参数 (sswCore.c:50-52):


p->nFramesK      = 1;    // 归纳深度
p->nFramesAddSim = 2;    // 额外模拟帧
→ 模拟深度 = nFramesK + 1 + nFramesAddSim = 4 帧

&scorr 默认参数 (cecCore.c:188-193):


p->nWords  = 15;   // 15 × 32 = 480 bits
p->nRounds = 15;   // 15 轮
p->nFrames = 1;    // 1 帧展开
两者模拟宽度差不多，但关键差异在于：SSW 的初始模拟包含 BMC 阶段的 SAT 驱动细化（Ssw_ManSweepBmc 真正用 SAT solver 处理每个节点），而 &scorr 的 BMC (Cec_ManLSCorrespondenceBmc) 也用 SAT，但是通过 SRM Miter 批量处理，不是增量的。

差异 4：SAT 冲突预算

scorr:   nBTLimit = 1000  (per node)，且持久 SAT solver 允许更深的搜索
&scorr:  nBTLimit = 100   (per output)，且 fUseCSat=1 (CBS，无学习)
CBS (Cbs_ManSolveMiterNc) 没有 CDCL 学习，每次调用都从零开始搜索。这不仅是预算问题，而是搜索能力的质性差异。

差异 5：CBS 噪声（你已发现并修复）
CBS 的后向 justification 只覆盖目标 RI 的锥，其他 RI fanin 任意赋值，导致 DFS 探索不可达状态。你的前向模拟修复解决了这个问题，但这只是冰山一角。

三、CBS DFS 让结果变差的真正原因
即使 forward simulation 修复后，CBS DFS 作为初始模拟的唯一来源有根本性缺陷：

CBS 产生的 pattern 数极少：conflict limit 打到就返回 -1，实际有效 pattern 可能只有个位数。而随机模拟产生 32 * nWords * nRounds = 480 * 15 = 7200 bits。

CBS DFS 探索局部状态空间：从全零 reset 状态出发的 DFS 只探索"早期可达状态"，对于大多数等价类（在遥远可达状态才可区分）完全无效。

被 CBS DFS pattern 替代了随机模拟：看 cecCorr.c:968-976——Cec_ManSimClassesSatGuided 在 Cec_ManSimClassesPrepare 和 Cec_ManSimClassesRefine 之后运行，但 CBS DFS pattern 的质量不如随机模拟那样均匀分布，导致初始类结构比原版还差。

五、你的 CBS DFS 工作在整体框架中的定位
你的 CBS DFS（现在有了 forward simulation 修复）是正确的方向，但位置不对。它应该是：


随机模拟（大量 patterns，覆盖宽）
    ↓
CBS DFS（少量 patterns，针对性强，探索可达状态边界）
    ↓
MiniSAT incremental sweep（证明力强，有学习）
    ↓
深度 SRM (nFrames=2)（处理剩余难题）
而不是单独替代初始随机模拟。CBS DFS 最适合作为"发现有趣可达状态"的补充工具，帮助分裂那些随机模拟恰好未能区分但理论上可达状态会区分的类。

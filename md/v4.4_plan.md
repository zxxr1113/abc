分区优化策略分析：以 SAT 求解效率为目标
0. 先重新框定问题
你说"普通线性切分质量损失可接受，瓶颈在每分区的 SAT 求解速度"——这把问题从"找更好的分区"变成了"让每个分区的 scorr 跑得更快"。这是关键定位转变。SAT 速度的真正瓶颈是什么：

因素	占比	是否可被分区策略影响
候选等价对数量（决定 SAT 调用次数）	高	✓ 强影响
单分区 TFI 锥规模（决定单次 CNF 大小）	高	✓ 强影响
Refinement 迭代次数（CEX-driven）	中	△ 间接
Speculative reduction 链长度（化简 CNF）	中	✓ 间接
跨分区学习子句浪费	中	✓ 强影响
所以分区策略的直接目标应该是：单分区候选对少 + TFI 锥小 + 同类候选聚集（spec reduction 友好）+ 不同分区间共享 SAT 状态。

1. 对你给出的 4 个方向的诚实评估
#1 模拟签名聚类 — ★★★ 推荐做，但要带"SAT 难度"维度
理论依据：同一仿真等价类的寄存器在 scorr 内部要互相做 SAT 比较；如果它们被切到不同分区，跨分区比较就丢了。同分区内的等价类成员越多，speculative reduction 链越长，CNF 越简，SAT 越快。

但是有一个隐藏陷阱：同签名的寄存器既可能"很好证（真等价）"也可能"很难证（伪等价，需要多轮 refine）"。如果某个分区聚了 200 个高难度候选对，它会成为 wall-clock 瓶颈。

正确做法：复合 key


struct RegSig {
    uint32_t simSig;       // 仿真签名（前 32 位仿真哈希）
    uint16_t refineCost;   // 该寄存器在初始 sim refinement 中的迭代代价
    uint8_t  classSize;    // 它所在等价类大小（log scale）
};
// 排序键: simSig 主键，refineCost 副键
// 这样既聚同类，又把"难/易"分散到不同分区平衡负载
C 实现复杂度：低。只需要 Cec_ManSimulation 跑一次仿真（已有），按签名 qsort，按 refineCost 二级排序。约 80 行。

#2 控制信号约束（reset/enable） — ★★ 价值真，但识别难
理论依据：被同一 enable 信号控制的寄存器有对齐的可达状态空间。它们的等价性证明在归纳步中共享前提条件 → SAT 学到的子句可以共享。

陷阱：

经过 RTL 综合后，enable 已被 absorb 进 D 输入的 MUX，结构上不显式可识别
探测 reset：找寄存器 D 端形如 MUX(rst, const, normal_logic) — 可行但要写专门的模式匹配
多 clock domain 已经在 ABC 里有处理（pAig->vClockDoms），但 enable 没有
实现复杂度：高。需要 MUX 模式探测 + clock-enable 信号扇出图分析。ROI 不如 #1，建议劣后。

#3 超图切分（hMetis 风格） — ✗ 不推荐
为什么否决：

目标错配：hMetis 最小化"边切割数"，但 SAT 难度不等于切割边数。一个 1 切割的分区可能有非常深的 TFI 锥，照样 SAT 慢
外部依赖：hMetis 是 LGPL 库，引入到 ABC 主线不现实
图构造开销：100K AIG 节点的超图本身要 O(N) 构造、O(N log N) 切分，对中等电路已经接近 scorr 时间
GIA 实现困难：超图节点是 AIG 节点，超边是 fanout。构造 + 调用 hMetis + 反向映射回 GIA 寄存器组——~500 行代码 vs 收益不明确
结论：跳过。如果将来真要做，不如自己写一个轻量级"贪心 Jaccard 聚类"（见我下面方向 E），10% 代码量 80% 效果。

#4 重叠窗口（overlapping windows） — ✗ 反向优化
评估：和你的目标完全相反。

重叠窗口的目的是 覆盖更多跨分区等价（提质量）
但 总 SAT 时间增加（重叠区域被多次证明）
你说"质量损失可接受"，那就更不该花时间做重叠
唯一例外：如果做"反例驱动 refinement"，每次 refine 时对反例锥做一次"小重叠"（仅锥扩张），那是 CEGAR 思路。但那不属于 partition 改进，属于 scorr 内部改进。

2. 我建议的更优方向（按 ROI 排）
方向 E — TFI 签名 Jaccard 聚类 ★★★★（我的首推）
理论依据：单分区的 SAT 复杂度 ≈ O(2^|TFI(partition)|)。最小化每个分区的 |TFI ∪ over partition's regs| = 让分区内寄存器的 TFI 高度重叠（共享支撑）。这正是 ICCAD'08 §3.3 提到的 attraction/repulsion 评分的 SAT 速度版。

核心算法：


// 每个寄存器 r：用 32-bit 仿真签名压缩 TFI 集合作为 fingerprint
// (运行 1 次 32-word 仿真，每个寄存器记录其 driver 的 sim signature)
unsigned * pTfiSig = ABC_ALLOC(unsigned, nRegs);
Gia_ManSimRandom(pAig, 32);  // 复用现有仿真
for each reg r:
    pTfiSig[r] = pAig.simWord[Gia_ObjFanin0(R_driver)];

// 贪心聚类
for each unassigned r:
    seed cluster with r
    while cluster.size < nPartSize:
        find r' s.t. popcount(pTfiSig[r] & cluster_sig) maximal  // attraction
        cluster.add(r'); cluster_sig |= pTfiSig[r']
实现复杂度：约 150 行 C。仿真已有；聚类是简单贪心；不需要外部库。

预期收益：单分区 TFI 锥规模降低 30-50%（因为 linear partition 把不相关寄存器混进来，TFI 锥肿胀），SAT 时间近似线性下降。

方向 B — 全局 fraig 预扫 ★★★★（最廉价的大头）
理论依据：候选等价对数 = scorr 工作量上限。fraig 把组合等价点合并掉，候选对自然减少。

实现：


Gia_Man_t * pFraiged = Cec_ManSatSweeping(pAig, NULL, 0);
// 然后对 pFraiged 做 partition + scorr
实现复杂度：5 行。直接调现有 API。

预期收益：典型电路候选对数减少 30-50%；scorr 时间近似线性下降。这是论文 dsec 流程里"先 fraig 再 ssw"的标准做法，从来就不该跳过。

方向 A — 难度均衡再分配 ★★★（特别在并行下重要）
理论依据：partitioned scorr 的 wall-clock = max(partition_time)，不是 sum。如果 99 个分区 1 秒，1 个分区 500 秒，wall-clock = 500 秒。难度均衡能直接降低 max。

核心算法：


// Phase 1: 先按 #1 (sim affinity) 做初分
// Phase 2: 估每分区难度
//   difficulty(P) = nCandidatePairs(P) × avgLevel(P) × log(|TFI(P)|)
// Phase 3: 二分搜索阈值 T，把 difficulty>T 的分区拆分，<T/4 的合并
//   保证 max/min < 4
实现复杂度：~100 行。

预期收益：单线程 1.5x（避免最难分区拖累），并行 N 核可达 N×。

方向 F — 跨分区增量 SAT ★★★★★（最高潜力，但工程量大）
理论依据：相邻分区共享大量 TFI 锥（因为 linear partition 在 RTL 顺序上往往把数据通路相邻寄存器分到相邻分区）。它们 scorr 调用产生的学习子句 80%+ 是相同的。每分区独立从零跑 SAT 是浪费。

实现思路：


SatSolver * pShared = sat_solver_new();
// 把 pAig 的全部组合 CNF 一次性加进 pShared
encode_full_aig_into_solver(pShared, pAig);

for each partition P:
    // 用 assumption literals 限定本分区的候选对、目标 RI
    Vec_Int_t * vAssumps = compute_partition_assumps(P);
    Cec_RunScorrIncremental(pShared, P, vAssumps);  // 复用 pShared
    // 学习子句保留到下一分区
实现复杂度：高（300-500 行）。需要侵入 Cec_ManLSCorrespondenceClasses，把它的 SAT 调用从 "create solver per call" 改为 "shared solver"。

预期收益：典型 3-5×，最坏 1.5×（取决于分区相似度）。

建议：作为 P1 长期工作，不放在第一波改进里。

方向 D — 自适应分区大小 ★★（小优化）
理论依据：scorr 内部 BCP 在大分区上的边际效率快速下降。控制逻辑分区可以做大（1500-2000 reg），算术分区应做小（300-500 reg）。

实现：


// 估每个寄存器的预期 SAT 难度
//   easiness(r) = 1 / (depth(r) × xor_density_in_TFI(r))
// 累计 easiness 直到达到一个目标"工作量预算"
// 这样大寄存器组（控制）+ 小寄存器组（算术）混合存在
实现复杂度：~50 行。

预期收益：10-20%，主要来自避免"过大分区被难寄存器拖累"。

4. 一句话总结
你列的 4 个方向里：#1 是好方向但要加难度维度，#2 价值真但识别难（劣后），#3 不值得做，#4 反向优化。

真正高 ROI 的是你没列出的两条：

方向 B（全局 fraig 预扫） — 5 行代码 30-50% 加速，没理由不做
方向 E（TFI 签名 Jaccard 聚类） — 替代 linear partition 本身，30-50% 加速 SAT，原理对、实现轻
加上你的 #1（升级为带 difficulty 维度的复合 key）做第三梯队。这三件事叠加期望 2-3× 整体加速，且都不需要碰 scorr 内部，风险可控。

Commit 2 — CEX lifting module (abc_version/abc_cexlift)
New file cecCexLift.c (~270 lines):

Ternary propagation: seeds pCare[]/pVal[] from active cube literals (CBS's unset CIs are naturally X), does a single topological pass through all ANDs, checks the target CO.
Greedy dropping: tries each literal; if CO stays at definite-1 without it, drops it permanently (accumulates across iterations for the next trial).
Replication: replica 0 = bare lifted cube; replica k≥1 = lifted cube + one randomly-selected free-CI pin. The extra pin forces Cec_ManLoadCounterExamplesTry to use a different bit-slot → different random background from Cec_ManStartSimInfo.
CLI: &scorr -L toggles lifting (off by default), &scorr -L -K 4 sets replication to 4. Verbose mode (-v) also prints [CEX-LIFT] stats per round.

Key design notes:

Gia_ManStop(pSrm) is now deferred until after lifting (SRM must be alive for ternary sim).
Multiple CEXes don't clobber each other — existing Cec_ManLoadCounterExamplesTry conflict detection handles all cases.
fCexLift=0 by default → zero behavior change without -L.

cecCexLift.c — complete rewrite
Bit-parallel ternary sim (TernaryBatch64)

Scratch arrays are now Word64 (unsigned long long) — bit k of each word encodes trial k
In a batch of 64 literals, trial k tests dropping literal batch_start+k. One single memset + one forward AND-graph pass produces the drop-bitmask for all 64 trials simultaneously
Only the nLits cube literals are seeded — unset CIs remain X naturally. No full-CI scan
Complexity: O(⌈nLits/64⌉ × nAnd) vs old O(nLits × nAnd)
Greedy across batches, non-greedy within

Drops from batch 0 flow into batch 1's seeding (the dropped literals' CIs stay X)
Within a batch, each literal is tested with its 63 batch-peers still present — this is the non-greedy approximation
Soundness: an unsound lifted cube (where two co-dependent literals were both dropped) merely fails to split equivalence classes; it never causes incorrect merges
Adaptive K (Cec_ManCexLiftAndReplicate)

Pre-scan counts nRecs before lifting begins
K_actual = clamp(64 / nRecs, 1, K_max):
nRecs=1 → fill all 64 sim slots (K=K_max up to 64)
nRecs=64 → K=1, no replication (batch already full)
nRecs>64 → K=1, Cec_ManLoadCounterExamples auto-batches
K_max = nCexReplicate (default now 1 = lift-only; use -K 8 to enable)
Usage

&scorr -L          # ternary lift only, no replication
&scorr -L -K 8     # lift + adaptive replication up to 8×
&scorr -L -K 64    # lift + max replication (fill entire sim batch)

XCGRP-CEGAR 路线诊断与重构方案
核心论断（先给结论）
你目前的实验数据糟糕，根因是算法定位错误——同时做了两件互相打架的事：

Case-split（pivot 常量化）：sound + lossless，目标=加速 SAT
Level-truncation（CO 回溯 L 层）：sound but 会漏等价，目标=缩小问题
合成结果是"既要全电路无损（为质量），又要截断加速（为时间）"——两个目标互相吃掉对方。这就是你 L=0 慢、L=64 优化归零的根本原因。

你自己悟到的那点是对的：论文 Table 3 已经证明 lossy partition 的质量损失只有 0.3-0.4%、运行时省 45%。所以 XCGRP 不应该跟 -P 抢"分区"这个职位，应该去抢"加速器"这个职位。

矛盾一：颗粒度——XCGRP 应该嵌入 -P 内层，而不是替代它
路线重定位

[现在]  whole_circuit → 2^N case-splits → intersect
            ↑ 跟 -P 抢饭碗，且没赢

[建议]  whole_circuit → ABC -P linear partition (1000 regs/part)
        FOR each partition:
            → fraig                      // 收组合等价，减少候选对
            → 2^N case-split (XOR pivot) // 加速本分区的 SAT
            → scorr inside cofactor
            → intersect 本分区
        merge cross-partition (论文已证 lossy 可接受)
关键实现挂钩点（abc 内部）
外层分区：复用 cecCorr.c 中 -P 路径走的 Gia_ManRegPartitionLinear / Gia_ManRegCreatePart
在每个 part 上调你的 Cec_ManXcgrpCegarCorrespondence 替代当前的全电路调用
N 不需要大：每个分区已经只剩 ~1000 reg + 其 TFI，N=2（4 分支）足够；纯加速器，不再背"质量"的锅
矛盾二：抽象边界——别在 AIG 锥内截断，要在寄存器边界停
为什么 CO + L 层 在时序问题上必然垮
信号等价 = 可达状态上的关系；level-cut 切的是组合锥，但等价依赖跨帧约束（RI→RO）
把 RO 当 free PI 是 scorr unrolling 内部已经做的事——你在外层再 free 一遍组合中间节点 = 双重过近似
当 cone(a) 走过 reg→AND→...→深 AND，你在第 L 层切掉，free var 替换了"实际由别的 reg 约束的信号"。scorr 看到自由变量下 (a,b) 不等价 → 丢弃。L=64 优化归零就是这个机制
正确的抽象边界：候选对驱动的 COI（不是固定 L）

function build_abstraction_for_target_set(pAig, target_pairs):
    cone = ⋃ (COI(a) ∪ COI(b)) for (a,b) in target_pairs
    # 自然边界：原 PI、原 RO、cone 之外的节点
    # 不在组合中间冒出 free var
    return Gia_ManDupCone(pAig, cone)

"logic-cone-oriented 减少 SAT 时间"这个目标本身值得做，但代价是只在寄存器边界停——这正是 -P 分区做的事
所以矛盾二的回答是：接受现实，把"在锥中间截断"这条路砍掉，改用"以候选对 COI 为单位、以 RO 为天然边界"的抽象
你 v4.1 中 Xcg_DupRecBounded 应该重写为
不再按 pDistToCo[i] > nLevelLimit 切；改为按"是否在当前 partition 的 reg 集合的 TFI 内"切——切点全是 PI/RO，不会出现 abstract-AND-PI 这种东西。

矛盾四：CEX 驱动精化——你的判断是对的，但精化目标搞反了
关键认识：你的抽象不会产生假等价
数学事实：

pivot cofactor + 跨分支 intersect = 还原 C 的等价类（sound）
level-truncation 把 deep logic 替换为 ∀f：等价类只会更少不会更多
所以"random sim validate 抓不到假等价"不是 sim 弱，而是根本就没有假等价可抓。Validate 步骤目前唯一的作用是给 scorr 当备份保险，不是 CEGAR 的精化触发器。

正确的 CEGAR 触发器：漏网之鱼，不是伪等价

function CEGAR_for_completeness(pAig, partition):
    EP_sim = simulation_classes(pAig)            // 仿真上限
    abs = build_abs(pAig, partition.regs)
    EP_proved = scorr(abs)                       // 抽象下证出
    suspects = EP_sim \ EP_proved                // 漏网集合（真正的精化对象）

    for (a, b) in rank_by_likelihood(suspects):
        if global_dead.contains((a,b)): continue
        
        // 用 SAT 在抽象上单独跑这一对
        result = scorr_single_pair(abs, a, b)
        if result == UNSAT:
            EP_proved.add((a,b))
        elif result == SAT(model):
            // 反例可能伪：abs PI 取了不可能值
            cex_input = project_to_PI_RO(model)
            if simulate(pAig, cex_input)[a] != simulate(pAig, cex_input)[b]:
                global_dead.add((a,b))           // 真反例
            else:
                // 伪反例 → 找出最离谱的 abs PI，inline 其驱动锥
                target = pick_inline_target(model, abs.absPIs)
                abs = inline(abs, target)
                retry

一句话总结
把 XCGRP 从"全电路无损分区方案"重新定位为"ABC -P 分区内的 SAT 加速器"——外层用 -P 解决"质量 vs 速度"（论文已证 lossy 损失 <0.4%），内层用 case-split 解决"单分区 SAT 太慢"，CEGAR 的精化对象从"伪等价"改为"漏网等价"。这样四个矛盾全部对齐：颗粒度 = 寄存器分区，抽象 = 分区 COI（边界天然落在 PI/RO），跨分支共享 = 增量 SAT + fraig + dead pool，精化触发器 = EP_sim \ EP_proved。

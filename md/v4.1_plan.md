XCGRP 算法深度分析
我先快速核验了当前代码状态：cecXcgrp.c 504 行，实现结构与记忆一致。以下分析基于 ICCAD'08 (Mishchenko et al.) 和 ISVLSI'15 (Mukherjee et al.) 两篇论文的核心观点展开。

问题一：时序依赖下的"锥体扩张"风险
1.1 ABC 传统切分 vs XCGRP 的本质差异
ICCAD'08 §3.4 明确指出了一个关键事实：无损分区（lossless partitioning）对 signal-correspondence 不可行。原因是 k-step induction 需要 k+1 帧展开，而第 k 帧的约束会通过寄存器反向传播到所有早期帧的扇入锥。论文的经验数据是"partitions 经常膨胀到几千个寄存器"，并最终退化为 lossy partitioning（按寄存器索引顺序硬切，外部寄存器当自由变量）。

对比来看：

维度	ABC lossy partition (-P)	XCGRP 常量传播
切分单元	寄存器组（外部变量→free var）	单个 XOR 枢轴（pivot→const）
时序锥是否膨胀	膨胀：每帧都需要独立展开分区的 TFI	视枢轴位置而定
精度损失	有（lossy，割边自由化引入假反例）	无（常量分支是 case split）
任务数量	O(#regs / partition_size)	2^N（N=枢轴数）
XCGRP 对锥体膨胀的抑制能力是条件性的——不是普适性优势：

有利情况：如果枢轴位于组合逻辑的"瓶颈点"（比如加法器进位链的某一位、AES S-box 前后的 XOR 汇合点），常量化后所有扇出锥都会塌陷，且这种塌陷会被 Gia_ManHashXor/And 在每帧展开时重复触发（因为每帧的组合逻辑副本共享同一枢轴常量）。
不利情况：如果枢轴处于寄存器之后的组合逻辑中，对当前帧有强化简效果，但对 k 步归纳中其他帧的寄存器状态影响极弱。SAT 求解的瓶颈往往不在"每帧展开后的逻辑规模"，而在"跨帧约束的耦合强度"——这点 XCGRP 不解决。
1.2 能否穿透时序帧边界？
不能完全穿透，且存在反馈环路致命缺陷。

关键观察：当 pivot V=0 时，当前帧内所有 V XOR x 被化简为 x、所有 V·x 被化简为 0。但在 k 帧展开的图中：

如果 V 是组合信号（PI 或组合节点），V 在不同帧是不同的变量实例 V_0, V_1, ..., V_{k-1}。XCGRP 只对单帧的 V 施加约束；要让所有帧的 V 都为常量，需要引入时序不变量 □(V=c)，而这本身就是一个待证明的性质——不成立。

如果 V 是寄存器输出，情况更糟。寄存器的值由上一帧的寄存器输入决定，反馈回路意味着 V_t = f(V_{t-1}, ...)。强制 V_0=0 不意味着 V_1=0，除非 V=0 是不变量。

结论：XCGRP 的常量传播化简效应严格限定在单帧组合逻辑内。对于 k-step induction 的 k 帧展开，XCGRP 需要做的正确操作是：在每一帧副本上独立施加 V_t = c 约束，这会让任务数变成 2^k 而非 2。目前代码（根据记忆）只在原始 GIA 上做一次常量传播再由 scorr 展开，这在语义上只约束了归纳基 base case 的第 0 帧，对 inductive step 的剪枝效果有限。

反馈环路失效场景：若枢轴 V 驱动了某个寄存器 R，而 R 的扇出又回到 V 的 TFI，那么 V=const 与 R 的时序转移函数会在归纳步中产生矛盾约束——SAT 求解器会快速返回 UNSAT，看似"证明成功"，实则剪掉了合法的可达状态，产生 false equivalence。这就是 ICCAD'08 Theorem 依赖"no further restructuring"的深层原因——任何破坏归纳对齐（inductive alignment）的操作都会让 completeness 丢失。

问题二：Trace Partitioning 思路的等价性检查适用性
2.1 XOR 密集型电路的 SAT 空间收缩
对算术/加密电路，XCGRP 的核心杠杆是XOR 链的线性代数结构。一条长度 L 的 XOR 链 y = x_1 ⊕ x_2 ⊕ ... ⊕ x_L 在 CNF 下需要 O(2^L) 或 Tseitin 编码 3L 个子句，但传播极弱——MiniSat 的 BCP 对 XOR 几乎不做单元传播，必须等 L-1 个输入确定才能决定输出。

当把中间节点 x_i 固定为常量时：

链被切成两段 x_1⊕...⊕x_{i-1} 和 x_{i+1}⊕...⊕x_L（或一段，若 x_i 是端点）；
每段的 SAT 决策树深度减半；
重要：在 AIG 重新 hash 时，Gia_ManHashXor 会触发结构共享，如果链参与了多个 XOR 汇合点（如 Sbox），收益是乘性的。
理论上界估计：若枢轴位于 L 链中点，单帧求解复杂度从 O(2^L) 降到 2 × O(2^{L/2})，即开方级加速。这与 ISVLSI'15 Table I 中 FP multiplier/divider 从"不终止"变为可验证的实验现象吻合。

但注意：该加速对 signal correspondence 的多数瓶颈帮助有限。ICCAD'08 §3.2 观察到 scorr 的运行时主要花在"satisfiable SAT runs + counter-example simulation"，即反例驱动的 refinement 循环。XCGRP 减小的是单次 SAT 调用的规模，不减少 refinement 轮次。

2.2 "无损性" vs 物理切分
这是 XCGRP 相对于 ABC -P 的真正理论优势。形式化陈述：

设原电路 C 的等价类集合为 EQ(C)，XCGRP 在枢轴 V 下生成子问题 C₀, C₁。则：

EQ(C) = EQ(C₀ | V=0) ∩ EQ(C₁ | V=1) （Case-split 的 soundness + completeness）
而 lossy partition 只有：

EQ(C) ⊇ EQ(P_1) ∩ EQ(P_2) ∩ ...（单向包含，因为割边自由化后 P_i 的行为是 C 的过近似，会漏等价）
对 completeness 的实际帮助：

无 false-negative 等价类丢失：lossy partition 常见病理是两个寄存器在原电路中因共同的外部寄存器输入而等价，但分到不同 partition 后该输入成了两个独立自由变量，等价性就无法证明。XCGRP 不产生自由变量，只做 case analysis，因此所有原本可证的等价都仍可证。

支持组合与时序一体化：XCGRP 在组合图上做切分，scorr 引擎照常 k-induction，两者正交。这与 lossy partition 需要专门的 partition-aware 归纳算法不同。

代价：任务数 2^N 的指数增长。ISVLSI'15 对 USB PHY / Ethernet MAC 用 2 个 transaction 分区就取得"不终止→2 万秒"的突破，但分区数不能无限扩张。

问题三：优化方向
3.1 多枢轴（2^N 分支）
建议：谨慎引入，且需配合解耦度量。

收益模型：N 个枢轴 → 2^N 任务，每任务规模 ≈ 原规模 / 2^(αN)（α 是"枢轴化简效率"，α∈(0,1]）。加速比 ≈ 2^(αN) / 2^N = 2^{-(1-α)N}——仅当 α 接近 1 时加速。

实践建议：

选择 fanout-disjoint 的枢轴：若 N 个枢轴的 TFO 不相交，它们的化简效应独立叠加，α 接近 1；
枢轴相关性检测：用 structural support intersection 判断，|support(v_i) ∩ support(v_j)| / |support(v_i) ∪ support(v_j)| < 阈值才入选；
限制 N ≤ 3（即 ≤ 8 个任务）作为工程妥协，与 ICCAD'08 partition 压缩到 8~16 的工程结论一致；
并行调度：2^N 任务是 embarrassingly parallel，当前 pthread 路径已支持，但需要动态负载均衡（某些分支会被常量传播秒杀，某些需要完整求解）。
3.2 K-step induction 中的动态枢轴
建议：不要在 k 展开过程中更换枢轴，但可以在 refinement 迭代间更换。

理由：

k-induction 同一轮内，所有 k+1 帧副本必须施加相同约束才能保持 inductive 结构的一致性（ICCAD'08 Theorem 依赖的 feedback edge set 对应性）；
每帧换枢轴会破坏 speculative reduction 的常量传播链，因为不同帧的等价类假设需要一致；
合理时机：scorr 的外层 refinement 循环（ICCAD'08 Fig 3.2 的 do-while）之间，根据当前已证等价类更新枢轴评分——因为已合并的节点会改变 XOR 链结构。
3.3 与 ABC 内部精简的深度耦合
除 Gia_ManHashXor/And，建议按此顺序级联：

Gia_ManAigSyn2 / Dar_ManRewrite：DAG-aware rewriting（DAC'06）。常量传播会暴露大量 2-input / 3-input cut 上的局部优化机会，drw 能把它们收走。
Gia_ManDupDfsClasses + Cec_ManSatSweeping：轻量级 SAT sweep 合并组合等价，减小子问题初始规模。
Gia_ManFraigSweep (fraig)：ICCAD'08 Fig 4.1 在 ssw 之前也调了 fraig，逻辑一致。
Dam_ManMultiExtract：XOR/MUX 多输入提取，能把被部分坍塌的链重新识别为宏节点。
Gia_ManResub：再替换可以利用新暴露的 don't-care。
实现层面建议在 Gia_ManXcgrpSplitOnConst 返回后链式调用 Gia_ManAigSyn2 + Cec_ManSatSweeping，再喂给 scorr 引擎。

核心问题：锥体膨胀的替代切分方法（文献检索）
针对"切分导致锥体膨胀"这个本质矛盾，学术界已有若干更系统的思路，XCGRP 可以重构借鉴：

A. 基于时序抽象的切分（替代而非补充）
Phase Abstraction (Bjesse & Kukula, ICCAD'06) — ICCAD'08 参考文献 [6]。对周期性信号自动识别相位，合并等价相位的帧。用在 XCGRP 之前做预处理，可以把 k 帧归纳的 k 减半。
Temporal Decomposition / Target Enlargement (Baumgartner et al.) — IBM SixthSense 的核心之一。对寄存器做 reachability-guided simplification，把时序问题转成局部组合问题。Ref: Baumgartner, Mony, "Scalable sequential equivalence checking across arbitrary design transformations", ICCD'06。
B. Localization Abstraction / CEGAR 风格切分
Kurshan 的 Localization Reduction 和 Clarke 的 Counterexample-Guided Abstraction Refinement：不预先切，而是从最小抽象开始，按反例增量加回寄存器。对时序等价检查，Jain et al. "Word-Level Predicate-Abstraction and Refinement" (TCAD'08) 给了系统方法。
关键优势：锥体大小由反例驱动而非结构启发式决定，避免一次性切大导致膨胀。
与 XCGRP 融合：把 XOR 枢轴当作"第一候选抽象谓词"，反例再选下一个。
C. IC3 / PDR 式归纳泛化（现代主流）
IC3 (Bradley, VMCAI'11) / PDR (Een et al., FMCAD'11)：不做显式展开，通过逐帧 frame sequence + 归纳泛化求解。ABC 里是 pdr。
对等价检查的启示：Mony, Baumgartner 在 "Exploiting Suspected Redundancy Without Proving It" (DAC'05) 后续工作中，把 IC3 风格的 frame generalization 用到 scorr 上，避免 k 帧 monolithic 展开。
工程落地：可以把 XCGRP 的枢轴常量作为 IC3 generalization 的 seed lemma（"V=0 or V=1"），让 IC3 自动扩展到时序归纳。
D. 接口切分 / Assume-Guarantee（结构性）
Compositional SEC (Khasidashvili et al., ICCAD'04) — ISVLSI'15 参考文献 [14]。在模块接口上做切分，而不是在组合锥内部切。对有明显层级的设计（如 USB PHY, Ethernet MAC）效果远好于 AIG 级切分。
与 XCGRP 对比：XCGRP 的 XOR 链评分看不到模块边界；接口切分利用设计 hierarchy，锥体扩张被模块 I/O 天然截断。
E. Bit-slicing for Datapath（算术电路专用）
Andrade et al., "Bit-Level Abstraction for Arithmetic Circuits"：对加法器、乘法器按位切片，每切片是独立的小 SAT。本质上是"按数据维度而非控制维度切"。
Sayed-Ahmed et al., "Equivalence Checking Using Grobner Bases" (FMCAD'16)：用多项式代数而非 SAT 处理 XOR 密集算术——对 Montgomery 乘法器等 XOR 天文数字的电路有质的飞跃。
F. CEGAR-based Cone Refinement（针对你的具体痛点）
最贴合"抑制锥体膨胀"的现代方法是 Lazy Cone Abstraction：

Goel, Sapra, Chockler 等人在 "Abstraction-Based Satisfiability Solving of Presburger Arithmetic" 系列中提出，先用 free variable 切掉锥体，求解；若返回 SAT 反例，检查是否 spurious，spurious 则沿反例路径加回最小充分锥。
这直接解决 ABC -P 的 lossy 问题：切分不再是一次性的精度损失，而是反例驱动的精确化。
实现建议：在 XCGRP 外层加一个 CEGAR loop，初始用激进的 lossy split，反例触发时沿反例的 justification frontier 恢复 free variable 为原电路逻辑。
推荐优先级
对你当前的 fastlec 分支，我建议的研究路线：

短期（工程优化）：实现 3.1 的多枢轴 + 3.3 的 rewriting 链，立即可拿性能数据；
中期（方法论）：加 CEGAR-style refinement（方向 F），把 XCGRP 从"一次性 case-split"升级为"反例驱动 case-split"，这直接解决问题一的锥体膨胀；
长期（研究贡献）：探索与 IC3/PDR 的融合（方向 C），让时序归纳自然整合，而不是在组合层做文章再喂给 k-induction。
核心论断：XCGRP 作为组合层的无损切分是有价值的优化，但不能直接解决时序验证的锥体膨胀问题——这个问题的本质是 k-induction 的跨帧约束耦合，需要在时序抽象（phase abstraction / IC3）或反例驱动精化（CEGAR）层面解决。建议把 XCGRP 定位为"SAT 调用内的加速器"，而把"抑制膨胀"的职责交给外层的时序抽象引擎。

完备性论证
soundness：一对 (a,b) 被接受的必要条件是

在全部 2^N 个常量分支上，scorr 在抽象电路都判等价 AND
原电路 512 位随机仿真下从未反例
交集语义下：任一分支否决即被丢弃。随机仿真是概率过滤器，但上层 &scorr 后续还会复核，漏网之鱼会被兜底。

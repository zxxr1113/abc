三、可行性评估 + 改进算法（超越 FastLEC）
FastLEC Algorithm 1 的局限性
FastLEC 针对的是组合电路的 SAT 变量切分（cube-and-conquer 模式）。直接移植到 &scorr 的问题：

&scorr 处理的是时序电路的寄存器等价性，不是单次 SAT 问题的变量切分
关键瓶颈是等价类的分组与验证顺序，而非单个 SAT 实例的分治
FastLEC 的评分函数 $\text{sc}[v] = |c|^2/d$ 针对组合扇入锥，对寄存器的时序传播特性没有建模
提出更好的算法：XOR-Cluster-Guided Register Partitioning (XCGRP)
核心思想：在 &scorr 中，寄存器分区的质量决定 SAT 求解的局部性。若一个分区内的寄存器对应同一算术字（如 32 位加法器的各个进位寄存器），SAT 求解器可以利用局部算术规律快速证明等价。

算法设计（四步）：

Step 1：XOR 链识别与寄存器着色

对每个 RO（寄存器输出），沿扇入锥DFS：
  统计到达 RI 的路径上的 XOR 门数 → xor_depth[i]
  识别连续 XOR 门序列 → 属于哪条 XOR chain
  记录每个链的长度 → chain_len[chain_id]

时间复杂度：O(|E|)，与现有 Gia_ManCreateRegSupps 相似
关键数据：Gia_ObjIsXor(pObj) 已可直接判断，无需额外预处理。

Step 2：改进的寄存器评分函数
不同于 FastLEC 的 $|c|^2/d$，针对时序寄存器设计：

$$\text{score}(r_i, r_j) = w_{\text{chain}} \cdot \text{shared_chain}(r_i, r_j) + w_{\text{depth}} \cdot \frac{1}{1+|\text{xor_depth}(r_i) - \text{xor_depth}(r_j)|} + w_{\text{supp}} \cdot \frac{|\text{supp}(r_i) \cap \text{supp}(r_j)|}{|\text{supp}(r_i) \cup \text{supp}(r_j)|}$$

$\text{shared_chain}$：两个寄存器是否在同一 XOR 链上（最重要因子）
$\text{xor_depth}$ 差距：同一算术字的各位寄存器 XOR 深度相近
Jaccard 支持集相似度：复用已有的 Gia_ManCreateRegSupps
这比 FastLEC 更好的地方：加入了 xor_depth 的差值项，显式捕捉"同一算术字的不同位"这一模式，而 FastLEC 只看单个节点到 PO 的距离。

Step 3：图聚类分区

// 伪代码

    // 1. 建立寄存器相似度图（稀疏，只考虑分数 > 阈值的边）

Vec_Int_t * Gia_ManComputeXorChainIds( Gia_Man_t * p )
{
    Gia_Obj_t * pObj;
    Vec_Int_t * vChainId = Vec_IntStartFull( Gia_ManObjNum(p) );
    int i, nChains = 0;
    // DFS 标记：连续 XOR 序列分配同一 chain_id
    Gia_ManForEachAnd( p, pObj, i ) {
        if ( !Gia_ObjIsXor(pObj) ) continue;
        int id0 = Gia_ObjFaninId0(pObj, i);
        int id1 = Gia_ObjFaninId1(pObj, i);
        int c0 = Vec_IntEntry(vChainId, id0);
        int c1 = Vec_IntEntry(vChainId, id1);
        // 继承或新建链
        if ( Gia_ObjIsXor(Gia_ManObj(p, id0)) && c0 >= 0 )
            Vec_IntWriteEntry( vChainId, i, c0 );
        else if ( Gia_ObjIsXor(Gia_ManObj(p, id1)) && c1 >= 0 )
            Vec_IntWriteEntry( vChainId, i, c1 );
        else
            Vec_IntWriteEntry( vChainId, i, nChains++ );
    }
    return vChainId;
}

4.2 并行模型的三个关键缺陷
缺陷一：无子分区间通信

每个分区在独立线程中运行完整的 Cec_ManLSCorrespondenceClasses，分区 A 中发现的等价性对分区 B 的求解毫无帮助。在算术电路中，一个字节的寄存器等价通常意味着相邻字节也等价——这一"蝴蝶效应"被完全屏蔽。

缺陷二：粗粒度调度，无负载均衡

sswPart.c:196-207 的调度逻辑：


// 主线程循环：扫描可用线程并分配任务
while ( Vec_PtrSize(vStack) > 0 ) {
    for ( i = 0; i < nProcs; i++ ) {
        if ( atomic_load_explicit(&ThData[i].fWorking, ...) )
            continue;                          // 线程正忙，跳过
        ThData[i].p = Vec_PtrPop( vStack );    // 弹出下一个分区
        atomic_store_explicit(&ThData[i].fWorking, true, ...);
        break;
    }
    // 注意：外层循环没有 sleep，是忙等待！
}
这是一个无 sleep 的忙等待主循环。当所有线程都在工作时，主线程 100% CPU 占用只是在检查 fWorking 标志。对于大型分区（单个分区可能运行数分钟），主线程会长期无效占用一个 CPU 核心。

缺陷三：无引导式工作窃取

大的分区和小的分区被同等对待。一个含有 1000 个复杂 XOR 链寄存器的分区可能比含 100 个简单触发器的分区慢 100 倍，但调度器无法感知这一差异，导致严重的负载不均衡（木桶效应）。

&scorr 增量化改造的深度分析
读完 v3.0.md 和日志后，我认为你之前失败的核心原因不在"增量"本身，而在选错了增量的层次。下面是我的分析。

1. 重新诊断瓶颈（基于日志）

Srm   = 16.27s (9.15%)   ← SRM 重建
Sat   = 107.76s (60.58%) ← SAT 求解
Sim   = 7.15s (4.02%)
Other = 46.70s (26.25%)
TOTAL = 177.88s (332 iter)
关键事实：

收敛尾段（iter 3~332）每轮 c=0、lit 仅减 1–2，但仍耗 0.25–0.7s
60% 时间在 SAT，且绝大多数 miter 求解结果是"再次 UNSAT"——它们上一轮已经被证明等价了，这一轮只是因为 SRM 重建+solver 冷启动而被迫重证
真正可省的不是 SRM 构建，而是"重证已证"。

这就回答了 v3.0 为何退化：rIC3-style domain masking 攻击的是"单次 SAT 内决策空间"，但 &scorr 的痛点是"跨轮重复证明"。Domain mask 在去掉 speculative reduction 后 CNF 暴涨，得不偿失，你已经发现了。

2. 正确的增量化层次：Proof Obligation 级，而非 CNF/Solver 级
核心观察：在 speculative reduction 框架下，pair P 在第 r 轮的证明结论之所以可能失效，当且仅当第 r-1 轮被证伪的某个 pair Q 出现在 P 的 TFI 锥（在 k-帧展开后的 SRM 中）。

把 SRM 看作一个"假设依赖图"：

每个 candidate pair P_i 的 miter 输出 m_i 在 SRM 中的逻辑值，依赖于其 TFI 上所有被 speculatively 替换过的节点 R_j
一旦 R_j 被证伪，m_i 才需要重证；否则 m_i 上一轮 UNSAT 的结论仍然成立（单调性：移除假设不会让原本 UNSAT 变 SAT，但反之——R_j 假设被撤销后，UNSAT 证明的 clause 可能失效）
⚠️ 严格来说撤销假设后 UNSAT 不一定保留——因为 UNSAT proof 可能用到了 R_j 假设。所以 P 必须重证当且仅当 P 的 TFI 中至少有一个 R_j 是上一轮新近被证伪的 pair。这就是 TFO 触发条件。

3. 算法设计：Active List + TFO Trigger
数据结构

typedef struct Cec_IncrMgr_t_ {
    Vec_Int_t * vActivePairs;     // 本轮需要证明的 pair 索引
    Vec_Int_t * vDisprovedLast;   // 上轮被证伪的 pair（触发源）
    Vec_Int_t * vProvedStable;    // 已稳定证明的 pair（永久跳过，直到触发）
    Vec_Int_t * vTfoMark;         // 节点 -> 时间戳，避免清零
    int         nStamp;
    Vec_Int_t * vRepr2Pairs;      // repr 节点 -> 所有以它为代表的 pair（反向查表）
} Cec_IncrMgr_t;
vRepr2Pairs 是关键：给定 TFO 中一个节点 X，O(1) 查到 X 是否是某 pair 的 obj 端，以及哪些 pair 以 X 为 repr。

TFO 计算（k 帧展开）

// 在原始 AIG 上计算 k-frame TFO（不在展开后的 SRM 上做）
void Cec_CollectTfoK(Gia_Man_t * p, Vec_Int_t * vSeeds, int nFrames,
                     Vec_Int_t * vTfo) {
    Vec_IntClear(vTfo);
    int f, i, Id;
    Vec_Int_t * vCur = Vec_IntDup(vSeeds);
    Vec_Int_t * vNext = Vec_IntAlloc(64);
    
    for (f = 0; f <= nFrames; f++) {
        // 1. 组合 TFO 闭包（在当前帧内）
        Gia_ManIncrementTravId(p);
        Vec_IntForEachEntry(vCur, Id, i)
            Gia_ManCollectTfo_rec(p, Id, vTfo);
        
        if (f == nFrames) break;
        
        // 2. 跨帧：通过 RI -> RO 边推到下一帧
        Vec_IntClear(vNext);
        Vec_IntForEachEntry(vTfo, Id, i) {
            Gia_Obj_t * pObj = Gia_ManObj(p, Id);
            if (Gia_ObjIsRi(p, pObj)) {
                int RoId = Gia_ObjId(p, Gia_ObjRiToRo(p, pObj));
                Vec_IntPush(vNext, RoId);
            }
        }
        ABC_SWAP(Vec_Int_t *, vCur, vNext);
    }
}

for (r = 0; r < nIterMax; r++) {
    // === Step 1: 计算本轮 active pairs ===

            // pair 是 (iNode, repr(iNode)) 或以 iNode 为 repr 的所有
            int iPair = pMgr->pNode2Pair[iNode];
            if (iPair >= 0 && !Vec_IntFind(pMgr->vProvedStable, iPair))
                Vec_IntPush(pMgr->vActivePairs, iPair);
        }
        Vec_IntFree(vSeeds);
    }
    
    if (Vec_IntSize(pMgr->vActivePairs) == 0) break;  // 收敛
    
    // === Step 2: 构建仅含 active miter 的 SRM ===
    // 关键改动：Gia_ManCorrSpecReduce 仍然用所有 pair 做 speculative substitution，
    // 但只为 active pair 生成 miter PO
    pSrm = Gia_ManCorrSpecReduce_Active(pAig, nFramesCur, fScorrGia,
                                         pMgr->vActivePairs);
    
    // === Step 3: SAT 求解 ===
    Cec_ManSatSolveMiter(pSrm, pPars, &vCexes);
    
    // === Step 4: 处理结果 ===
    Vec_IntClear(pMgr->vDisprovedLast);
    Vec_IntForEachEntry(pMgr->vActivePairs, iPair, i) {
        if (sat_unsat[i]) {
            Vec_IntPushUnique(pMgr->vProvedStable, iPair);
        } else {  // SAT - 反例
            Vec_IntPush(pMgr->vDisprovedLast, iPair);
            Cec_ManRefineByCex(pAig, vCexes[i]);  // 模拟精化
            // 注意：模拟精化可能拆分更多 class，把这些也加入 vDisprovedLast
        }
    }
    Gia_ManStop(pSrm);
}
4. 关键设计决策
4.1 保留 Speculative Reduction（这是与 v3.0 的根本区别）
Gia_ManCorrSpecReduce_Active 内部仍然对所有未被证伪的 pair 做 substitution（保持 SRM 极小），但只为 vActivePairs 添加 miter PO。这样：

SRM 大小：与原来基本相同（可能略小，因为已证伪 pair 不再 substitute）
SAT 工作量：从 |所有 pair| 降到 |active pair|
学习子句：每轮 solver 仍然销毁，但单轮内的工作量已大幅降低
4.2 不要碰 sat_solver 的增量复用
跨轮复用 sat_solver 在这个架构下不划算：

SRM 每轮拓扑变化（已证伪的 pair 不再 substitute），变量 ID 重新分配
跨轮保留学习子句需要稳定的变量编号 → 必须维护一个全局编号空间 → 退化为 v3.0 的全局 CNF 路径
ROI 低：日志显示 Sat 60% 中绝大部分将被 active list 直接消除，剩余的冷启动开销可忽略
结论：sat_solver 不动，CBS 更不动。CBS 在 &scorr 主路径上不是瓶颈，改造它没有必要。

4.3 模拟精化的连锁反应
模拟精化（Cec_ManRefineByCex）会基于反例对所有 class 重做分区，可能把"我们以为稳定"的 pair 也拆掉。处理方法：


// 精化后，把所有受影响的 class 中的所有 pair 都标记为 disproved
// （而非仅仅显式 SAT 返回的那个）
for each class C that was split during refinement:
    for each pair P in old C:
        if P->repr changed:
            Vec_IntPush(vDisprovedLast, P);
            Vec_IntRemove(vProvedStable, P);
这一步必须保守——任何 class 拓扑变化都视为该 class 内所有 pair 被"证伪"以触发 TFO。

5. 回退策略（应对大规模拆分）

#define FALLBACK_RATIO 0.3  // active pair 超过总数 30% 时回退

if (Vec_IntSize(pMgr->vActivePairs) > FALLBACK_RATIO * nTotalPairs) {
    Cec_CollectAllPairs(pAig, pMgr->vActivePairs);
    Vec_IntClear(pMgr->vProvedStable);  // 重置稳定集
}
回退到全局扫描时，开销与原版本一致——最坏情况下不会比原版更慢，这是 v3.0 没能保证的关键性质。

6. 预期收益
基于日志分析：

iter 1–2 (BMC 后)：active list ≈ 全部，与原版相同
iter 3–10：每轮拆 1 个，TFO 通常 < 1000 个节点 → active pair 几十个 → SAT 时间从 0.7s 降到 ~0.02s
iter 11–332：尾段 ~95% 的迭代每轮拆 1 个，TFO 锥极小
乐观估计：107s SAT → ~15s，总时间 178s → ~80s，2.2× 加速。

实测前我不会承诺 3-5×——你日志里 "Other" 26% 包含了模拟、复制等无法通过 active list 优化的部分，那部分是 Amdahl 上限。

7. 实施优先级
先做 active list + 部分 miter SRM（不动 solver、不动 spec reduce 主体），实现 Gia_ManCorrSpecReduce_Active，主循环改造，TFO 触发
测量基准：用同一个 Problem05 跑对比
仅当步骤 1 收益 < 30%，才考虑跨轮 solver 复用
这个路线与 v3.0 的本质区别：v3.0 想"少决策"，实际增量化目标应该是"少证已证"。前者动 solver、动 CNF 结构，风险大；后者只动 SRM 的 miter 输出选择，speculative reduction 的优势被完整保留。

关键正确性论证
不变式：若 pair P 上轮 UNSAT，且 P 的两端不在 TFO_k(seeds) 中，则 P 本轮仍 UNSAT —— 因为 P 的 SRM 子电路完全由 TFI(P) 内的 substitution 决定，TFI 与 TFO 互为反向闭包，所以 endpoints 不在 TFO 等价于 TFI 内无 substitution 改变。

三种局部化思路的本质对比
读完三份文档，我可以给你一个统一的视角来看这三种思路 —— 它们表面都叫 "COI 裁剪"，但裁剪的方向、粒度、和与 SAT 引擎的耦合方式完全不同，这直接决定了它们在 ABC 上是否可行。

1. COI 的方向与粒度：三种"切法"
方法	方向	粒度（裁剪对象）	触发问题
rIC3 Domain	TFI（后向）	决策变量（CNF var）	"这次 query 的可满足性依赖哪些变量？"
Per-pair (失败)	TFI（后向）	电路节点 + CNF 子集	"这一对 pair 的电路逻辑是什么？"
Active SRM (成功)	TFO（前向）	证明任务（miter PO）	"上轮哪些假设变了，哪些 pair 还需要重证？"
关键洞察：前两者问的是同一个问题（TFI 裁剪），第三种问的是它的对偶问题（TFO 触发）。

TFI 裁剪回答的是 "How to answer this query cheaply" —— 减少单次求解的工作量
TFO 触发回答的是 "Which queries need re-asking" —— 减少总查询数
v7 的 active list 之所以有效，是因为它意识到 &scorr 的痛点不在"单次 SAT 慢"，而在"重证已证"（v7.0_plan.md:14-19）。这是层次完全不同的优化：前两者优化 inner loop，第三种优化 outer loop。

2. Solver State Persistence：冷启动问题的根源
这是 per-pair 在 ABC 上注定失败的核心原因：

rIC3 Domain（持久化）

init_slv, ind_slv 在 Scorr::scorr() 整个生命周期内只构造一次
↓ 跨所有 check_scorr(x, y) 调用复用
↓ Learned clauses 持续累积（gipsat/eq.rs 还做在线 clause rewriting）
↓ VSIDS activity 历史保留
Per-pair（v3.0 路线）

for each pair:
    sat_solver_new()      ← malloc + 数据结构初始化
    Cnf_Derive()          ← AIG→CNF 转换，每个 AND 节点 3 clauses
    sat_solver_solve()    ← VSIDS 从零开始爬，无 learned clauses
    sat_solver_delete()   ← free，所有学习成果丢弃
为什么 per-pair 在 rIC3 能跑、在 ABC 跑不动？

rIC3 的 "per-pair" 其实根本不是 per-pair —— check_scorr(x, y) 复用同一个 ind_slv（scorr.rs:39, rIC3/scorr.md:54-65），domain mask 只是在已经持久化的 solver 上加一层决策过滤。真正 per-pair 的只有 enable_local() 这个 O(|TFI|) 的 BFS 标记动作。

而 ABC 的 sat_solver 接口设计假设是"每次 miter 一个 solver"。要在 ABC 里复刻 rIC3 的模式，必须维护一个跨轮稳定的全局变量编号空间，这就要求放弃 speculative reduction —— 而这一步直接把 SRM 撑爆（v3.0.md:251）。这就是为什么 v3.0 的"模仿 rIC3"在 ABC 架构下是个伪命题。

Active SRM
单轮内：所有 active pair 共享一个 solver，learned clauses 在 active pair 之间复用（这是 ABC 原生的 batch 优势）。
跨轮：solver 销毁，但轮内任务量已经被 active list 砍到极小（尾段每轮可能只有几十个 pair），冷启动开销被摊薄到可以忽略。

3. Speculative Substitution 的红利：物理剪枝 vs 逻辑屏蔽
这是最被低估、但对 ABC 最致命的一点。

Gia_ManCorrSpecReduce 做的不是裁剪，而是结构化合并：

一个等价类 {n1, n2, n3, n4} 在 SRM 中只剩 1 个代表节点
CNF 中只生成代表节点对应的变量和子句
Miter PO 检查"假设是否被违反"
Domain restriction 没有这个红利：

CNF 中所有 4 个节点的变量都存在
Watcher list 仍然要维护
BCP 仍然可能穿越这些变量
Domain mask 只阻止 VSIDS 主动 decide，但 unit propagation 不受限（v3.0.md:34）
对一个有 100K 节点、其中 60K 处于等价类的电路：

ABC 的 SRM：~40K 节点（合并掉 60% 重复）
等价的 "domain-restricted full CNF"：100K 节点（只是不主动决策其中 60K）
后者的 CNF 文件本身就大 2.5×，在 BCP/watcher 维护上的常数开销随之放大。物理剪枝把变量从 CNF 中消除，逻辑屏蔽只是不让它们进决策堆 —— 二者在常数因子上差一个量级。

v3.0 退化的根本原因（v3.0.md:251）就在这里：去掉 speculative reduction 后，CNF 暴涨抵消了 domain 的所有收益。

Active SRM 的精妙之处（v7.0_plan.md:124-130）：不动 speculative reduction，只过滤 miter PO 的发射。等价类 substitution 全部保留，SRM 大小与基线相同，但 active 任务量是 baseline 的 1%~5%。

4. 工程开销：上下文切换 vs 批处理吞吐

                Per-pair          Domain-restrict       Active SRM
单次 query 开销   高 (rebuild)      低 (BFS+heap rebuild)  N/A (batch)
Query 数量        N (pair 数)       N                      N_active << N
Batch amortize    无                无                     有
ABC 原生契合度    极差              差                     好
ABC 的 Cec_ManSatSolveMiter 是为多 miter PO 的单次 solve 优化的：一次 solve 调用可以让 SAT 求解器在多个 PO 之间复用 learned clauses（这是 ABC 主路径上 batch 加速的来源）。

Per-pair 把这个 batch 红利完全抛掉，每对独立 solve
Domain restrict 在 ABC 上需要先放弃 spec reduce 才能 incremental → 失去 batch 优势
Active SRM 完全保留 batch，只是把 batch 的输入从"全部 pair"换成"上轮 TFO 触及的 pair"
这就是 v7 比 v3 快的工程层面原因：它顺着 ABC 既有的批处理纹路走，而不是逆着改。

5. 为什么你模仿 rIC3 失败、保留 SRM 反而成功？
把三种思路放回 &scorr 的工作模型来看：


&scorr 的真实瓶颈 = (单轮 SAT 时间) × (轮数)
                  = O(|SRM_CNF|) × O(N_iter)
思路	攻击的因子	ABC 上的代价
rIC3 Domain	减小 |SRM_CNF| 的有效搜索空间	必须放弃 spec reduce → |CNF| 暴涨 → 净亏
Per-pair	把 |SRM_CNF| 拆成 N 个小 CNF	失去 spec reduce + 失去 batch + 冷启动 → 三重亏损
Active SRM	直接砍掉 N_iter 的乘数（每轮任务量）	只动 miter PO 选择 → 保留所有现有红利
深层联系：rIC3 的 domain（TFI）和 v7 的 active list（TFO）其实是同一个依赖图的两个方向。rIC3 在 query 内向后扫 TFI 找"我需要谁"；v7 在轮间向前扫 TFO 找"谁需要我重证"。它们在 rIC3 中能并存，是因为 rIC3 用的是单一持久化 solver + 单调累积的等价集，两个方向都低成本。在 ABC 中只能选一个 —— 而 TFO 这一侧（active list）与 spec reduce + batch SRM 的组合正交，TFI 这一侧（domain）与 spec reduce 冲突。

结论：时间-空间权衡的统一框架
思路	时间复杂度焦点	空间复杂度	适配前提
rIC3 Domain	单 query O(|TFI|) decisions	持久化 CNF（高，长期驻留）	单一持久 solver + 稳定变量空间
Per-pair	单 query O(|micro-SRM|)	瞬时（低，每对释放）	无 batch、单 query 廉价
Active SRM	单轮 O(|active| × |SRM|)	单轮 CNF（中等）	现有 batch 框架 + 跨轮可识别"什么变了"
真正的教训：移植算法时要识别"算法 idea"和"承载它的架构契约"是分离的。rIC3 的 domain restriction 不是孤立的优化，它依赖 gipsat 的持久化 solver + DagCnf 的稳定 var ID + 无 spec-reduce 的 CNF 模型。把 idea 摘下来塞进 ABC，承载契约破坏了，idea 就变成了反优化。

v7 的成功在于你换了一个与 ABC 架构契约兼容的 idea：保留 spec reduce 的物理剪枝红利，保留 batch SRM 的吞吐红利，只在更高层次（轮间任务集）做增量。这个层次恰好是 ABC 原始设计中没有覆盖的空白 —— 没有架构冲突，纯增量收益。

一、架构对比：两种"缩小搜索空间"的哲学
1.1 ABC 的方式：物理电路切除（Structural Reduction）
Gia_ManCorrSpecReduce 的本质是重建一个更小的电路：


原始 AIG (全局) ──────────────────────────────────
  pObj ──→ pRepr (speculatively merged)
  ↓
Gia_ManCorrSpecReduce_rec() : 递归 DFS 展开 nFrames 帧
  ↓
产出 pNew: 一个全新的 Gia_Man_t（SRM）
  ↓
Gia_ManCleanup() → 删除死节点
  ↓
Cec_ManSatSolveMiter() : 对 pNew 做 CNF 转换，新建 sat_solver，求解
  ↓
销毁 pNew 和 sat_solver
关键点：cecCorr.c:113-216 的 Gia_ManCorrSpecReduce 对所有候选对统一建立一个大 SRM，而非每对一个子图。这是一个批处理设计——代价是 SRM 可能仍然很大。

Gia_ManCorrSpecReal 的推推规则（cecCorr.c:54-71）：AND节点展开，RO节点向前滚帧——这是一个完整的时序展开，本质上是 BMC unrolling + speculative substitution 的融合。

1.2 rIC3 的方式：决策域掩码（Variable Masking）
domain.rs 的本质是不动 CNF，只动 VSIDS：


// enable_local: BFS 标记 TFI cone
self.domain.insert(r);
for d in dc.dep(v).iter() { self.domain.insert(*d); }

// push_to_vsids: 只把 domain 内的变量压入决策堆
// 非 domain 变量永远不会被 decide()
domain.rs:127-145 的 push_to_vsids 是关键：它不阻止单元传播穿越非 domain 变量，但 SAT 求解器永远不会主动对 domain 外的变量做分支决策。这意味着：

非 domain 变量只能被"强迫赋值"（propagation），不会被"猜测"
如果 TFI 锥外的变量对可满足性没有贡献，它们天然被忽略
1.3 本质区别分析
维度	ABC SRM (物理切除)	rIC3 Domain (决策掩码)
内存模型	每次迭代分配新 Gia_Man_t	一个全局 CNF 长期驻留
CNF 构建	每轮重新转换（O|SRM|）	一次性构建，之后增量
学习子句	每次销毁，无法复用	跨 Query 保留，积累质量
VSIDS 分数	每次重置为初始值	历史分数保留，分支更准
局部性保证	硬性保证（圈外节点不存在）	软性保证（propagation 可越界）
正确性	完整（SRM 保留语义等价）	完整（solver 完备，只是决策受限）
二、性能瓶颈诊断
2.1 ABC 的开销来自哪里
以 Cec_ManLSCorrespondenceClasses 的主循环（cecCorr.c:1013）为例，每轮迭代：


Gia_ManCorrSpecReduce()    → 遍历所有候选对，递归展开 nFrames 帧，分配新节点
                              成本：O(nCandPairs × nFrames × avgTFIdepth)
Gia_ManCleanup()           → DFS mark/sweep
CNF 转换（内部）           → 每个 AND 节点 → 3 clause，CI → 1 var
sat_solver_new/delete      → malloc/free 大量内存
求解                       → 冷启动，无历史学习
核心瓶颈：每一轮 r，即使只有少数新反例，也要重建整个 SRM 和 Solver。对于有 100K+ 候选对的大电路，SRM 依然可以有几万个节点。

2.2 rIC3 的 enable_local 为什么快
domain.rs:30-52：


pub fn enable_local(&mut self, domain: impl Iterator<Item = Var>, dc: &DagCnf, _value: &VarAssign) {
    self.reset();  // 只是 truncate Vec，O(|domain|)，无 free
    for r in domain { self.domain.insert(r); }
    let mut now = self.fixed;
    while now < self.domain.len() {
        let v = self.domain[now]; now += 1;
        for d in dc.dep(v).iter() { self.domain.insert(*d); }
    }
}
reset() 只是重置 Vec 的长度指针（domain.rs:23-28），内存不释放。VarSet 底层是 Vec<Var> + Vec<bool>，BFS 就是数组遍历，cache 友好。

对比 ABC 的 DFS 递归 + 新节点分配，rIC3 的 BFS 标记完全没有堆内存分配，是纯栈上操作（或已分配的长期 buffer）。

三、ABC 现有机制的评估
3.1 ABC 是否有类似接口
ABC 的 sat_solver（src/sat/bsat/satSolver.c）使用 MiniSAT 2.x 风格的 VSIDS order heap。关键结构：


// satSolver.h 中
struct sat_solver_t {
    ...
    veci        order;      // VSIDS heap (变量索引)
    int *       activity;   // VSIDS 分数
    ...
};
目前没有直接的"domain 变量过滤"接口。但有两个可利用的机制：

Assumption-based solving：sat_solver_solve(S, assumps, nAssumps, ...) 可以通过 activation literal 控制哪些 output 被激活，但不能限制内部变量的决策

Variable freeze/phase：MiniSAT 有 var_freeze/setDecisionVar 接口，ABC 的封装层暴露了有限子集

3.2 ABC 的 Partition/Window 机制
ABC 确实有 src/proof/fra/ 下的 window 提取，以及 Gia_ManPartition 等。但这些是结构级别的电路分割，每次依然要重建子图 + 转 CNF + 新 solver，本质还是 ABC 的物理切除路线，只是 SRM 更小了。它们并不解决 solver 冷启动和学习子句丢失的问题。

四、可行性分析与优化方案
4.1 方案可行性评估
在 ABC 的 GIA 数据结构中：

pObj->iDiff0 / iDiff1：fanin 的紧凑差值编码，可以反向得到 fanin
Gia_ManForEachObjReverse 系列宏：支持 DFS/BFS 遍历
pObj->fMark0 / fMark1：可用于 BFS 标记
p->pReprs / p->pNexts：等价类信息
TFI 锥计算可行：ABC 已有 Gia_ManCollectAnds, Gia_ObjMarkTfi 等工具函数，计算 TFI 代价低。

关键可行性判断：

如果对每对候选单独求解（而不是批处理SRM），domain restriction 才有意义
ABC 当前的批处理模式（所有对放入一个 SRM）与 domain restriction 在逻辑上是正交的
最有价值的改造是：增量 Solver + per-pair domain 限制
预期收益：对于大电路（>10K 候选对），学习子句复用 + domain 限制可以带来 3-10x 加速，接近 rIC3 的性能级别。

// 核心数据结构
typedef struct CecDomain_t_ {
    int *   pInDomain;   // 标记数组：CNF var -> bool (0/1)
    int *   pVarOrder;   // 当前 domain 内的变量列表
    int     nVars;       // domain 大小
} CecDomain_t;

// 对应 rIC3 的 enable_local
void Cec_DomainEnableLocal(CecDomain_t * pDom, Gia_Man_t * p, 
                            int iRepr, int iObj, int * pVarMap, int nFrames)
{
    // BFS from iRepr and iObj in the unrolled AIG
    // 使用 fMark0 标记 TFI 内节点
    int Queue[MAX_QUEUE], head = 0, tail = 0;
    Gia_Obj_t * pObj;
    
    // 清空上次标记（O(nDomainPrev)，而非全局清空）
    for (int i = 0; i < pDom->nVars; i++)
        pDom->pInDomain[pDom->pVarOrder[i]] = 0;
    pDom->nVars = 0;
    
    // 种子节点入队
    Queue[tail++] = iRepr; Queue[tail++] = iObj;
    pDom->pInDomain[pVarMap[iRepr]] = 1;
    pDom->pInDomain[pVarMap[iObj]]  = 1;
    
    // BFS 展开 TFI（跨帧，通过 Ro→Ri 边）
    while (head < tail) {
        int id = Queue[head++];
        pObj = Gia_ManObj(p, id % Gia_ManObjNum(p));
        // 加入 domain
        int cnfVar = pVarMap[id];
        if (cnfVar >= 0) {
            pDom->pVarOrder[pDom->nVars++] = cnfVar;
        }
        // 展开 fanin（AND节点）或前一帧的 Ri（RO节点）
        if (Gia_ObjIsAnd(pObj)) {
            // 加入 fanin0 和 fanin1 对应的展开 id
        } else if (Gia_ObjIsRo(p, pObj)) {
            // 找到对应的 Ri，在前一帧继续
        }
    }
}
Phase 3：VSIDS 过滤接口（需修改 sat_solver）
在 satSolver.c 中添加最小侵入式修改：


// 在 sat_solver_t 中添加
int * pDecisionMask;  // NULL 表示无限制，非 NULL 时只决策 mask[v]==1 的变量

// 修改 order_select 函数（decide 时的变量选择）
static inline int order_select(sat_solver* s, float random_var_freq) {
    // 原逻辑：从 heap 顶取变量
    // 新逻辑：如果 pDecisionMask != NULL，跳过 mask[v]==0 的变量
    int next = -1;
    while (heap_size(&s->order) > 0) {
        next = heap_removeMin(&s->order);
        if (s->pDecisionMask == NULL || s->pDecisionMask[next])
            break;
        next = -1;  // 跳过，继续取
    }
    return next;
}

// 新增接口
void sat_solver_set_domain(sat_solver* s, int* pMask) {
    s->pDecisionMask = pMask;  // 直接赋值，O(1)
    // 重新压堆（只压 mask 内的变量）
    heap_clear(&s->order);
    for (int v = 0; v < s->size; v++)
        if (pMask == NULL || pMask[v])
            if (var_value(s, v) == l_Undef)
                heap_insert(&s->order, v, var_activity(s, v));
}

五、结论与风险评估
预期收益（乐观估计）
学习子句复用：在大电路上，前 10% 的候选对产生的学习子句往往覆盖了后续 60% 的证明，这是 PDR/IC3 工具系列的核心优势
Domain 限制：将平均每对的决策变量从 O(|SRM|) 降至 O(|TFI_local|)，对深度有限的电路效果显著
综合加速：预计 3-8x，接近 rIC3 在 scorr 场景的性能
主要风险
全局 CNF 可能比批处理 SRM 大：Gia_ManCorrSpecReduce 内有 speculative substitution，会极大缩小 SRM 规模。去掉这步后 CNF 变大，抵消 domain 的收益——需要先做实验对比 SRM 大小 vs. 无 speculative reduction 的全局 CNF 大小
sat_solver 堆重建开销：每对候选都要重建一次 VSIDS 堆，如果 domain 很大（深层逻辑锥），开销不可忽视。可以用"lazy 重建"优化：只清空不合法变量，而非全清全压
ABC 的 sat_solver 封装层复杂度：satSolver.c 有多种 solver 变体（plain/proof/etc），修改需要同步多处
建议的实验步骤
先在不改 solver 的前提下，只实现 per-pair solving（每对独立 SRM，但极小）+ solver reset 但复用 clause DB，测量基准提升
再加入 domain 变量掩码，测量增量收益
最后考虑是否完全去掉 speculative reduction，改用全局 CNF
